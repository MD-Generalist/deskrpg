# 게이트웨이 연결 마법사

`/gateways` → 새 게이트웨이에서 로컬 / 원격 연결을 선택한다. 원격은 SSH 또는 게이트웨이 주소로 연결한다.

## 운영자 설정

호스트 설치·재시작 기능은 기본 비활성화다. DeskRPG 실행 환경에 `DESKRPG_HOST_SETUP_ENABLED=1`을 설정하고 앱을 재시작하면 `system_admin` 계정에만 로컬 검색이 표시된다. 일반 사용자는 주소 연결을 사용할 수 있다.

SSH 연결을 허용하려면 `DESKRPG_SETUP_SSH_HOSTS=dev-hermes,another-host`처럼 운영자가 승인한 SSH config 별칭을 설정한다. DeskRPG를 실행하는 OS 계정에서 별칭, SSH 키/agent, 검증된 known_hosts가 준비되어 있어야 한다. 미등록·변경된 호스트 키는 자동 수락하지 않는다. 패스워드나 개인 키를 웹 폼으로 받지 않는다.

호스트 실행은 Node 서버와 `python3`, SSH는 추가로 OpenSSH 클라이언트가 필요하다. 원격 Hermes는 Linux/macOS의 표준 `~/.hermes/hermes-agent` 설치와 Hermes가 생성한 사용자 서비스 정의를 지원한다. 임의 설치 경로·Windows 원격·관리되지 않는 프로세스는 자동 변경하지 않는다. 기본 Docker 이미지에는 SSH 클라이언트와 호스트 자격 증명이 준비되어 있지 않으므로 운영자가 이를 별도로 제공하지 않았다면 주소 연결을 사용한다.

로컬은 **DeskRPG 서버 호스트**를 뜻한다. 외부에 호스팅된 DeskRPG가 브라우저 방문자의 PC를 검색하는 기능은 포함하지 않는다.

## 로컬 및 SSH 흐름

1. 설치/프로필 검색 → 연결하기 → Hermes 버전, 플러그인 버전, 서비스 유닛, 시간대 사전 검사.
2. 검토 화면에서 등록할 프로필, 고정 플러그인 버전, 서비스 등록·플러그인 갱신·시간대 설정 여부, 설정 및 재시작 대상을 확인한다.
3. 설치 및 연결을 실행하면 서비스 등록(필요할 때), 플러그인 설치/갱신/활성화, API 설정, 시간대 설정(비어 있을 때만), 선택한 서비스 시작/재시작을 수행한다. 기존 키는 재사용하고 선택한 소유 프로필의 키가 없는 경우에만 생성한다.
4. 실제 API와 플러그인을 검증한 뒤 게이트웨이와 선택한 프로필만 등록한다. 프로필 화면에서 NPC 외형과 배치를 이어간다.

진행 단계는 `inspecting → installing_service → installing_plugin | enabling_plugin | updating_plugin → configuring_api → setting_timezone → restarting_gateway → verifying_gateway → saving_gateway → importing_profiles` 순서다. 필요 없는 단계는 건너뛴다.

개별 프로필 게이트웨이는 자체 프로필만 연결한다. 기본 게이트웨이에 여러 프로필을 묶는 경우 이미 실행 중인 개별 봇과 충돌할 수 있으므로 사전 검사에서 중단한다. 다른 프로필을 자동 종료하지 않는다.

외부 비밀 제공자를 쓰는 경우 기존 로컬 키로 인증이 확인되어야 한다. 제공자 설정을 덮어쓰거나 인증 키를 무조건 회전하지 않는다. 형제 프로필의 키가 없으면 마법사에서 임의 발급하지 않는다.

취소는 현재 명령이 안전하게 종료된 뒤 다음 단계 전에 적용된다. 이미 끝난 설치를 되돌린다는 뜻이 아니다. 프로세스 그룹 제한 시간 및 호스트 잠금으로 동시 설치를 방지한다. 실패 시 원인을 수정한 뒤 다시 확인한다. 진행 기록에는 인증 키나 원본 명령 출력을 저장하지 않는다.

설치 출력은 메모리에서 최대 256KiB까지 읽는다. 초과 시 설치 프로세스를 종료하고 실패 처리한다. 보안 스캔 차단과 저장소 접근 실패는 고정 오류 코드로만 전달한다. 알 수 없는 실패도 원문을 반환하지 않는다. 마법사는 **이미 설치된 구버전 플러그인을 고정 버전으로 갱신할 때만 `--force`를 사용한다.** 이때의 `--force`는 "기존 플러그인을 지우고 다시 깐다"는 뜻이며 보안 스캔을 우회하지 않는다 — 스캔이 차단하면 갱신도 `plugin_security_review_required`로 실패하고, 관리자가 해당 버전을 검토해야 한다. 최초 설치는 `--force` 없이 수행한다.

### Hermes 버전 하한

고정 플러그인 `0.6.0`은 Hermes `0.21.1` 이상을 요구한다. 사전 검사에서 설치의 `pyproject.toml` 버전을 읽어 비교하고, 낮으면 `hermes_version_unsupported`로 중단한다(호스트에서 `hermes update` 실행 후 다시 시도). 버전 문자열의 숫자가 아닌 꼬리(`0.21.1rc1`)는 비교에서 무시한다. **버전을 읽지 못하면 막지 않는다** — `hermes_version_unknown` 경고만 표시하고 그대로 진행한다. 읽기 실패로 멀쩡한 호스트를 차단하지 않기 위해서다.

### 플러그인 갱신

플러그인이 이미 설치돼 있어도 `plugin.yaml`의 `version`이 고정 버전보다 낮으면 갱신 대상으로 표시하고(`updating_plugin`), 고정 커밋을 `--force`로 다시 설치한다. 버전이 같거나 높으면 아무것도 하지 않는다(다운그레이드하지 않는다). 매니페스트가 버전을 적지 않아 읽을 수 없으면 갱신하지 않는다. 갱신 후 매니페스트 버전을 되읽어 확인하며, 실패는 `plugin_update_failed`로만 알린다. 갱신이 필요하면 재시작도 함께 예약된다 — 교체된 코드는 재시작 전까지 적재되지 않는다.

### 서비스 유닛이 없는 호스트

사전 검사에서 서비스 유닛을 찾지 못하면(`manual`) `installing_service` 단계가 추가되고, Hermes CLI의 `gateway install`을 호출해 유닛을 등록한다. **DeskRPG는 유닛 파일을 직접 쓰지 않는다** — Hermes가 만든 유닛만 기존 서비스 신원 검사를 통과하고, 그 검사를 통과한 서비스만 이후 재시작 대상이 된다. 설치 후에도 유닛을 확인하지 못하면 `service_install_failed`로 중단한다. 이 단계 역시 호스트 잠금·제한 시간·출력 상한을 그대로 따른다.

### 시간대

`config.yaml`의 최상위 `timezone`이 비어 있을 때만, 요청이 제시한 IANA 이름을 넣는다. 이미 값이 있으면 무시하고 덮어쓰지 않는다. IANA 이름 모양(64자 이하)이 아니면 `timezone_invalid`로 400 응답하며, 서버와 호스트 양쪽에서 같은 규칙으로 검증한다. 시간대를 보내지 않으면 이 단계를 건너뛰고 마법사는 그대로 진행된다. 쓰기는 기존 원자적 교체 경로를 쓰고, 되읽어 확인한다. 실패는 `timezone_write_failed`다.

## 주소 연결

API 주소와 기존 키로 Hermes 정체성, 인증, 플러그인을 순서대로 확인한다. 플러그인이 없는 정상 API는 등록할 수 있으나 준비 완료로 표시하지 않는다. SSH 설치 또는 고정 저장소의 설치 안내로 이어진다. URL만으로 최초 키 발급이나 누락된 플러그인 설치는 할 수 없다.

주소 입력에서 IPv4 링크 로컬, IPv6 링크 로컬 전체 대역, IPv4-mapped IPv6 및 메타데이터 호스트명의 끝 점 변형을 차단한다. 일반 IPv4 사설망과 루프백은 로컬 연동을 위해 허용한다. 이는 주소 문자열 검증이며 DNS 재바인딩까지 방어하는 네트워크 격리를 대체하지 않는다.

## 보존 데이터

게이트웨이/프로필 키는 기존 DB 암호화 저장 경로를 사용한다. 진행 기록은 `DESKRPG_HOME/gateway-setup`, SSH 대상 메타데이터는 `DESKRPG_HOME/setup-transports`에 보관된다. DB를 옮길 때 SSH 메타데이터도 함께 보존해야 한다. 메타데이터에는 키가 없으며 파일 권한은 0600, 디렉터리는 0700이다.

SSH 게이트웨이는 영구 대상 ID를 저장하고 요청 시 서버 소유의 루프백 터널로 해석한다. 앱 재시작 후 터널을 다시 만들 수 있다. 호스트 설치 스위치를 끄더라도 이미 등록된 SSH 연결은 유지된다. SSH 별칭을 허용 목록에서 제거하면 이후 연결을 거부한다.

## 검증 범위

2026-09-10: 로컬 Chrome에서 실제 설치 검색과 개별 프로필 검토, 원격 경로 선택을 확인했다. 설치/키 생성/서비스 제어는 임시 파일 및 가짜 서비스 실행기를 이용한 테스트로 검증했다.

실제 DanteServer SSH 연결에서는 기존 플러그인과 인증을 검증하고 `default`, `oliver`, `sophie`를 개발 DB에 등록했다. 최초 연결 프로세스의 터널을 종료한 뒤 개발 서버의 화면에서 연결 테스트를 실행하여 터널 재생성과 게이트웨이 인증을 확인했다. 원격 서비스는 준비 완료 상태여서 설치·재시작하지 않았다. Windows 원격은 테스트하지 않았다.

로컬 `noah`는 사용자 승인 후 로컬 저장소의 고정 커밋 `9e200eb1d2418d47c3b65a754ca111e13c5aafb4`를 CLI에서 `--force`로 설치·활성화했다. 이 설치 한 건만 스캔 차단을 우회했으며 전역 보안 설정은 변경하지 않았다. 이후 마법사의 실제 서비스 경로에서 API 설정, 해당 게이트웨이 재시작, API·플러그인 검증, 기존 키 재사용 및 프로필 등록을 완료했다.

현재 코드의 고정 GitHub 소스는 검사 당시 접근할 수 없었다. 배포 전에 접근 가능한 고정 설치 소스와 보안 검토 절차를 마련해야 하며, CLI 선행 설치가 필요했던 이번 검증을 신규 플러그인 자동 설치 전체의 종단 검증 완료로 간주하지 않는다.
