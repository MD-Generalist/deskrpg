# 회의 모드 엔지니어링 노트

- 좌석에 도착했는데 준비 상태가 계속 walking이면 도착 거리부터 늘리지 않는다. 늦은 일반 `seat:claim`이
  회의 예약을 일반 예약으로 교체하면 공간 도착 콜백이 사라진다. 같은 소유자의 같은 회의 좌석 재요청은 예약을
  유지한 성공으로 처리하고 일반 변경·해제는 거절한다. 실제 move→arrival 콜백과 개인 퇴장 예약 해제를 함께 검증한다.
- NPC 복귀 도착 뒤에도 `spatial` 예약 표식이 남으면 일반 좌석 변경이 `meeting_reserved`로 막힌다.
  도착·세대 검증을 마친 뒤 업무 위치에서는 일반 귀가처럼 예약과 원정 슬롯을 해제하고, 다른 실제 좌석에서는
  일반 도착 예약으로 전환한다. 복귀 중 보호, 물리 점유, 원정 수 제한과 이동 담당자 교체 후 좌석 변경도 함께 검증한다.
- 가구 텍스처가 늦게 도착하면 mapKey가 바뀌어 맵을 다시 그린다. 이를 실제 맵 변경으로 취급하면 회의 카메라가 풀린다.
  구조가 같으면 카메라는 유지하고 벽 참조만 재등록한다. 진짜 기하 변경에서는 기존 카메라·재질을 복원한다.
- Tiled 증축 바닥에 1을 하드코딩하면 빈 tilesets 또는 firstgid가 100인 유효 맵에서도 Phaser 로딩이 죽는다.
  정의가 확인된 기존 바닥 GID를 재사용하고 없으면 0을 쓴다. 뒤집기 비트는 유효성 판정 때만 제거한다.
  합성 테스트 맵도 tilesets가 비어 있으면 바닥 0을 사용한다.
- 회의실 근처 벽만 가림 후보로 등록하면 낮은 각도에서 외벽이 참가자를 가린다. 실제 건축 빌더의 외벽·유리·창틀도
  등록하고 개별 재질 복원이 가능하도록 배칭에서 제외한다. 바닥·가구·도시 배경까지 등록하면 안 된다.
- 증축의 미사용 셀을 막는 객체를 모두 그리면 수백 개 평행 파티션이 생긴다. 충돌 객체를 삭제하지 말고 생성 ID가
  명시된 벽의 렌더링만 경계와 코너로 제한한다. 저장·재정규화 후 ID/좌표 불일치는 표식을 무시하는 쪽으로 복구한다.
- 브라우저 검증에서 캔버스 존재만 기다리면 스폰 전에 클릭할 수 있다. player:spawn·players:state·npc:motion-state와
  실제 프레임 진행을 기다린다. 소켓 프레임의 ack 숫자가 붙은 `42<id>[...]`도 관찰 파서에서 처리한다.
