# 홈페이지 출근 장면 검증

이 검증은 공개 홈페이지와 로그인 화면만 다룬다. 실제 계정으로 로그인하거나 Hermes에 연결하지 않는다. 기존 게임 E2E와 별도 설정이며 `npm run test:e2e` 설정을 변경하지 않는다.

## 시각·보행 판정 기준

밝은 아침의 정교한 실물 미니어처가 목표다. 기존 도시 구도와 인물 외형을 보존하며, 사진풍 도시로 전면 교체하는 방향은 아니다. 나무는 외부 모델 구매 대신 가지와 개별 잎을 자체 생성한다. 다운로드·라이선스 부담 없이 경량 화면에서도 잎 윤곽과 빈 공간을 유지하려는 선택이다.

보행은 실제 GLB의 한 주기를 240회 표본 추출해, 최저 발 높이에서 2.5cm 이내인 뒤로 움직이는 접지 구간을 측정했다. 발의 왕복 전체 길이를 보폭으로 쓰면 공중에 있는 발의 전진까지 섞이므로 접지 구간의 속도로 한 주기 이동량을 계산한다. 좌우 발 평균에 모델의 월드 크기를 적용하며, 속도만 높이거나 뼈 크기를 바꿔 맞추지 않는다. 여섯 모델의 접지 기준 보폭은 1.82131~1.9212m, 원본 클립 주기는 약 1.04167초다. 발별 잔차의 최댓값은 5.13%로 허용 오차 10% 이내이며, 별도로 실제 장면의 발 접지와 전진을 연속 화면에서 확인한다.

## 실행

설치된 Google Chrome을 사용한다. 동일한 소스의 공개 모드 서버와 로그인 모드 서버를 먼저 실행한다. 이미 사용하는 개발 DB나 홈 디렉터리를 재사용하지 않는다. 각 서버의 `DESKRPG_HOME`과 `SQLITE_PATH`는 서로 다른 임시 디렉터리로 지정하고 `DATABASE_URL`과 `DB_TYPE`은 해제한다. 공개 서버에는 `COMING_SOON=true`, 로그인 서버에는 `COMING_SOON=false`를 적용한다. `NEXT_PUBLIC_COMING_SOON=true`로 빌드한 산출물은 로그인 모드 검증에 사용할 수 없다.

프로젝트 루트에서 `npm run build`를 완료한 뒤 별도 터미널 두 개에서 다음을 실행할 수 있다. 이 홈페이지 검증용 서버는 게임 소켓 서버를 기동할 필요가 없다. 테스트가 끝나면 각 터미널에서 Ctrl+C로 종료한다.

```bash
homepage_public_runtime=$(mktemp -d /tmp/deskrpg-homepage-public.XXXXXX)
env -u DATABASE_URL -u DB_TYPE -u NEXT_PUBLIC_COMING_SOON DESKRPG_HOME="$homepage_public_runtime" SQLITE_PATH="$homepage_public_runtime/runtime.sqlite" COMING_SOON=true npx next start --hostname 127.0.0.1 --port 3110
```

```bash
homepage_login_runtime=$(mktemp -d /tmp/deskrpg-homepage-login.XXXXXX)
env -u DATABASE_URL -u DB_TYPE -u NEXT_PUBLIC_COMING_SOON DESKRPG_HOME="$homepage_login_runtime" SQLITE_PATH="$homepage_login_runtime/runtime.sqlite" COMING_SOON=false npx next start --hostname 127.0.0.1 --port 3111
```

```bash
npx playwright test --config playwright.homepage.config.ts
```

기본 주소는 공개 `http://127.0.0.1:3110/auth`, 로그인 `http://127.0.0.1:3111/auth`다. 다른 서버를 사용한다면 다음과 같이 지정한다. 환경변수에는 `/auth`를 제외한 서버 주소를 넣는다.

```bash
HOMEPAGE_BASE_URL=http://127.0.0.1:3110 HOMEPAGE_LOGIN_BASE_URL=http://127.0.0.1:3111 npx playwright test --config playwright.homepage.config.ts
```

브라우저 안에서 초기 `GET /api/characters`만 401, `GET /api/auth/status`만 `{hasUsers:true}`로 응답한다. 로그인 폼 입력은 가짜 문자열로만 확인하고 제출하지 않는다. 계정 생성, 게임 진입, 운영 데이터 변경은 수행하지 않는다.

## 자동 검증 범위

- 공개·로그인 화면 각각 1440×1000, 2048×807, 390×844에서 HTML, 언어 전환, GitHub 링크 또는 폼 입력, 가로 넘침과 전체 스크린샷을 확인한다.
- 60초 동안 실제 렌더러의 차량 위치와 바퀴 회전을 수집한다. 차량 여섯 대, 다섯 차종, 양방향 이동, 정지·재출발, 같은 차선의 범퍼 간격을 확인한다. 여섯 GLB의 로드 상태, 실제 뼈대와 포즈 변화, 월드 좌표 이동도 확인한다.
- 포인터 시차, 모션 감소 시 렌더 프레임·포즈·바퀴·카메라 정지, 반복 화면 크기 변경 시 캐릭터 객체와 위치 유지 및 지오메트리·텍스처 수의 상한을 검사한다.
- 터치 지원 모바일 에뮬레이션에서 실제 Chrome 터치 스크롤 제스처로 문서가 스크롤되고 카메라는 그대로인지 확인한다.
- 실제 IntersectionObserver로 장면을 화면 밖에 보낸 뒤 정지와 복귀를 확인한다. WebGL 확장의 실제 컨텍스트 손실·복원도 실행한다.
- GLB 요청 중단 시 대체 캐릭터의 이동과 관절 변화, WebGL 미지원 시 독립 HTML 사용 가능 여부를 확인한다.
- 예상한 401, 의도적으로 중단한 GLB 요청 오류와 WebGL 초기화 실패만 좁게 제외한다. 나머지 콘솔 오류와 처리되지 않은 예외는 실패다.

테스트의 관찰 코드는 브라우저 시작 시 Three.js 개발 도구 이벤트를 구독한다. 운영 코드에 QA 전역 변수를 추가하지 않는다. PMREM 환경맵 생성용 렌더는 홈페이지 프레임 수에서 제외한다. 화면 밖 검사는 CSS 이동으로 실제 교차 관찰을 유발하며 페이지 숨김과 같은 검사라고 간주하지 않는다.

## 영상·근접 화면·성능 판정

결과 JSON은 `.artifacts/homepage-commute/results.json`, 테스트별 스크린샷·WebM 영상·실패 추적은 `.artifacts/homepage-commute/test-results/`에 저장된다. 60초 테스트의 첨부 JSON에는 실제 위치·포즈·렌더 통계가 들어 있다. 영상은 장면 진입과 로딩을 포함하므로 전체 길이가 60초보다 길다.

시각 검수에서는 영상에서 바퀴와 차체의 방향, 교차로 감속, 대기 중 바퀴 정지, 재출발, 도로 끝 소실을 확인한다. 보행은 한 주기 이상의 연속 프레임으로 발 접지와 미끄러짐을 확인한다. 뼈대가 움직인다는 자동 판정만으로 보폭의 시각적 품질을 승인하지 않는다.

나무 정면·측면 근접 화면과 도로·보도·건물·차량 재질 근접 화면을 변경 전후 같은 카메라에서 비교한다. 나뭇잎에 판형 십자나 단순 덩어리 인상이 남는지, 반복 텍스처가 과하게 드러나는지, 건물 형태와 글자가 유지되는지 검수한다. 기본 화면의 가독성도 함께 확인한다.

성능은 같은 기기·Chrome·뷰포트·모션 설정에서 로드 완료 후 30초씩 수집한다. 다른 빌드나 테스트가 CPU/GPU를 점유하는 동안 비교하지 않는다. 프레임 간격 median/p95와 `renderer.info.render.calls/triangles`를 함께 기록한다. 변경 후 p95가 변경 전의 1.25배를 넘으면 실패로 판단하고 원인 확인·조정 후 재측정한다. 모션 감소의 정지 프레임을 정상 모션의 성능 수치에 섞지 않는다.

기존 기준 자료는 `.artifacts/homepage-commute/before/`에 있다. 측정된 결과와 최종 근접 화면은 검증 실행 후 같은 상위 디렉터리에 보관한다. 390×844 검증은 데스크톱 Chrome의 모바일 화면 에뮬레이션이며 실제 휴대전화 검증이 아니다.

## 추가 수동 확인과 자원 소유권

실제 모바일에서는 터치 스크롤이 카메라를 끌지 않는지, 폼과 언어 선택을 가리지 않는지 확인한다. 실제 탭 전환으로 페이지를 숨긴 뒤 돌아와 순간이동 없이 재개하는지 확인한다. 페이지에 반복 진입·이탈하며 렌더 루프가 중복되거나 GPU 자원이 누적되지 않는지도 확인한다. 자동화에서 화면 밖 정지를 통과해도 실제 탭 숨김이나 React 제거 경로의 검증을 대신하지 않는다.

캐릭터 캐시와 공유 재질·텍스처의 소유권을 지켜야 한다. 장면 제거 시 캐릭터, 차량, 나무, 정적 배치, 환경맵, 그림자, 렌더러를 각 소유자가 해제해야 하며 공유 자원을 두 번 해제하지 않아야 한다. 화면 크기 변경에서는 장면 전체와 캐릭터를 재생성하지 않고 나무·차량의 품질만 전환한다. 컨텍스트 복원에서는 환경맵을 재생성하고 기존 캐릭터와 하나의 렌더 루프를 유지한다.

크기 변경 시 재질 텍스처는 최초 품질의 작은 맵을 재사용하고, 지오메트리와 그림자 품질을 전환한다. 화면 폭이 임계점을 오갈 때 텍스처까지 다시 생성하는 구조가 아니므로 재질 해상도가 매번 바뀐다고 판정하지 않는다.

## 실행 기록

2026-09-14, Apple M2 Max의 설치된 Chrome headless와 ANGLE Metal에서 측정했다. 성능 비교의 변경 전후 서버는 모두 Next.js Turbopack 개발 모드였으며, 아래 값은 각각 정상 모션 30초 측정이다. 자동 브라우저 회귀 검증은 별도로 프로덕션 빌드 서버에서 실행한다.

| 화면               | 프레임 수 전 → 후 | median(ms) 전 → 후 | p95(ms) 전 → 후 | render calls 전 → 후 | triangles 전 → 후 |
| ------------------ | ----------------- | ------------------ | --------------- | -------------------- | ----------------- |
| 1440×1000          | 1801 → 1802       | 16.7 → 16.7        | 16.7 → 16.7     | 133 → 243            | 235563 → 315259   |
| 390×844 에뮬레이션 | 1801 → 1802       | 16.7 → 16.7        | 16.8 → 16.7     | 133 → 243            | 235563 → 251819   |

두 화면 모두 p95 25% 악화 기준을 통과했다. 다만 렌더 호출과 삼각형 수가 늘었으므로 이 결과를 저사양 기기나 실제 휴대전화의 성능 보장으로 해석하지 않는다. 2048×807은 화면 검수용 1초·61프레임만 수집했으며 30초 성능 판정 대상에 포함하지 않았다.

원본은 `.artifacts/homepage-commute/before/baseline.json`과 `after/metrics.json`이다. `after/`에는 세 화면 크기, 나무 정면·측면, 차량·재질 근접 이미지, 보행자 여섯 명의 각 3프레임 및 `walking-frames.json`, 영상도 보관했다.

프로덕션 빌드의 공개·로그인 서버에서 `npx playwright test --config playwright.homepage.config.ts`를 실행해 13개 모두 통과했다(1.7분, 종료 코드 0). 두 테스트 파일의 TypeScript 검사와 ESLint도 종료 코드 0이다. 최초 실행에서 컨텍스트 손실 후 확장을 다시 조회하는 테스트 코드 오류를 발견했고, 손실 전에 얻은 확장 핸들을 유지하도록 수정한 뒤 전체 13개를 다시 실행했다.

기존 게임 설정으로 이 파일만 선택하는 `npx playwright test --config playwright.config.ts e2e/homepage-commute.spec.ts`는 13개 모두 건너뛰고 종료 코드 0이었다. 홈페이지 테스트는 전용 `homepage` 프로젝트에서만 실행되므로 기존 게임 검증 서버로 요청을 보내지 않는다.

실제 탭 숨김은 독립적으로 실행한 Chrome의 임시 프로필에 `connectOverCDP({noDefaults:true})`로 연결해 별도 검증했다. 기본 Playwright의 포커스 에뮬레이션을 적용하지 않은 상태에서 두 번째 탭을 실제 활성화하여 `document.hidden=true`를 확인했다. 1.8초 동안 렌더 프레임은 80으로 유지되고 여섯 캐릭터의 위치도 동일했으며, 원래 탭으로 복귀하면 밀린 시간을 한 번에 따라잡지 않고 재개했다. 별도 검증 명령의 종료 코드는 0이며 원본은 `after/lifecycle.json`이다.

전체 문서를 떠났다가 돌아오는 세 차례의 반복 진입에서도 캔버스 1개, 캐릭터 6명, 지오메트리 555개·텍스처 148개가 유지됐다. 이 검사는 전체 문서 재진입을 다루므로 React 컴포넌트만 제거하는 경로의 자원 해제 검사와 구분한다. 실제 휴대전화 검증은 수행하지 않았다.
